Road map

Planned improvements and features for Struggle Map

Bug Fixes

2

{ Fix filtering Bug

  • Category filter discards earlier entries. Currently events only show their most recent entry, and the category of previous entries is discarded. Fixing this, so for example when you filter to ballots, it shows all events with ballots, without removing them, is the plan.
  • Date range filtering has the same issue. Similar issue exists with date range filtering.
  • State filtering is unreliable. Filtering by state also has issues on occasion.

{ Improve UI Bug

  • AI sucks Currently UI is very basic and drawing from “vibe coded” style (ew). Improving this so it’s not the case would be good
  • Use proper SVG’s instead of Emojis for symbols
  • Fix Mobile Viewability Mobile Mode Currently has major issues with readability and text
  • Fix Filter Usability Filters are not very usable at the moment and would work better as a collapse menu

Short Term Features

2

{ Filtering by Union Done

Currently not possible to filter entries by Union.

{ Permanent links for Struggles Done

Each Struggle now has a shareable URL using its action ID. Selecting a Struggle updates the link, and opening that link restores the selected Struggle and its details.

{ Improve "types" for events Planned

Current event type list isn't that helpful. Could be good to improve this. Also remove key. Seems unnecessary. E.g. IEU publicises details of offer from the Vic. Catholic Ed. Auth. - Campaign Update (?)

{ Show events where other people wanted (Solidarity Actions?) Planned

Showing events where a union is calling for other people to join them to show up and join them and that being front and centre is important for the website.

{ Improve Performance Planned

  • Serving of JS file Currently all information is served up from one big data.js file. This works alright for now but as the amount of entries increase, it would be better to improve this by only serving up data from past month by default, and then letting people filter stuff as appropriate.
  • Slow Downs on mobile On Desktop rendering is fine and fast, but I have notice some issues on mobile
  • Union Filtering Currently unions are found by searching for individual strings and extracting them. Might be more dynamic, but costs performance. Makes more sense to just be an array of strings.

{ Collaboration Planned

  • Allow reporting of actions Currently there is a framework to report an event (Strike, lockout, Struggle e.t.c.), but server is not setup to handle requests. Setting up a way to handle the ability for people to file forms and then accept or reject if a Struggle is legitimate would be awesome.
  • Wiki integration This is more of a dream, but integrating with a media wiki instance which anyone can contribute to, and then tying links to each Struggle and also pulling information into each other would be awesome.

Long Term

2

{ Drop AI from data ingestion Collaboration

Use collaboration features to stop using AI for data ingestion.

{ Link to Barcode/Product Collaboration

Allow scanning of a barcode product in a major retailer and show information about workers/factory. Enables solidatiy.
